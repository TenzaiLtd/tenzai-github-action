# Tenzai Test GitHub Action

Public GitHub Marketplace action that triggers a fire-and-forget Tenzai commit-diff security test after a successful deployment.

## Structure

| Path                 | Purpose                                                        |
| -------------------- | -------------------------------------------------------------- |
| `action.yml`         | Marketplace metadata, inputs, branding, and Node 24 entrypoint |
| `src/main.ts`        | GitHub Actions SDK wiring                                      |
| `src/action.ts`      | Provider logic and Tenzai API calls                            |
| `src/action.test.ts` | Vitest unit tests                                              |
| `dist/`              | Committed production bundle generated by ncc                   |
| `examples/`          | Customer workflow examples                                     |

## Development

Use Node 24.15.0 and npm:

```bash
npm ci --ignore-scripts
npm run check
```

`npm run check` verifies formatting, typechecks, runs Vitest, and rebuilds `dist/index.js`. Commit source and production bundle changes together. Tests run directly with Vitest and must not be bundled into `dist/` or a separate test bundle.

CI repeats these checks and fails when rebuilding changes the committed production bundle. Keep `package-lock.json` synchronized with `package.json` and do not enable dependency lifecycle scripts without reviewing them.

## Action Contract

- Required inputs: `access-key` and `app-id`.
- Optional inputs: `dry-run` and `github-token`.
- The service-account key requires `app:read` and `scan:trigger` scopes.
- Production endpoints are fixed at `https://api.tenzai.io` and `https://app.tenzai.io`.
- Application targets are the source of truth; the action has no target, environment, server, commit-range, or output inputs.
- `to` is the current workflow SHA. `from` is the previous successful run SHA of the same workflow.
- The first successful workflow run skips because no previous deployment exists.
- Triggering is fire-and-forget. The Tenzai platform posts the eventual `Tenzai Test` check run and findings report.

Keep `src/action.ts` independent from process-global GitHub SDK state by injecting its dependencies through `run`. Tests should use Vitest spies and small typed dependency factories rather than importing the side-effecting `src/main.ts` entrypoint.

## Marketplace and Releases

GitHub Marketplace requires the primary `action.yml` at the repository root. Keep exactly one root action metadata file. The production bundle path in `action.yml` must continue to exist in every published ref.

Publish immutable semantic releases such as `v1.0.0` and maintain the corresponding rolling major tag, such as `v1`, for customer workflows. Marketplace publication is performed from the GitHub release flow.

## Supply Chain

- Pin third-party GitHub Actions to full commit SHAs with exact version comments.
- Commit lockfiles and install with `npm ci --ignore-scripts` in CI.
- Keep production dependencies minimal; development tooling must never enter `dist/index.js`.
- Never commit access keys, customer identifiers, or repository-specific deployment configuration.
